# 屋台にのきち レジアプリ 設計メモ

## 1. 何のためのアプリか

屋台「にのきち」でステーキ（1300円）ほか最大3品を売るときに使うアプリ。

一番困っているのは **焼き上がった商品を誰に渡せばいいか分からなくなること**。
だからこれは「お金を計算するアプリ」より前に、
**待っているお客さんと注文を結びつけるアプリ**として作る。お会計はそのついでに済ませる。

## 2. 直したいこと（困っている順）

1. 焼き上がった商品を、別のお客さんに渡してしまう
2. もう払った人に、もう一度お会計をしてしまう
3. 忙しいと注文そのものを忘れる・渡し忘れる
4. 片付けたあと、レジのお金と売上が合わない
5. 次回の仕込み量が勘になる

原因は **服装や顔を覚えて見分けていること**。
お客さんは動くし、上着を脱ぐし、似た服装の人も並ぶ。
しかも一番忙しいときに限って覚えきれなくなる。

## 3. 使う場面の決まりごと

| 項目 | 内容 |
|---|---|
| 商品 | 3品まで（ステーキ1300円＋あと2品）。**名前と値段を現地で直せること** |
| 使う機械 | スマホかタブレットを1台。これが正しい記録とする |
| 支払い | **現金だけ** |
| お金をもらう時 | **先払い**（注文を聞いたその場でもらう） |
| 人数 | 2人（焼く人と、注文を受ける人）。機械は注文を受ける人が持つ |
| 混むとき | **7組以上**が同時に待つ。焼く時間も長め |
| 番号札 | **配らない** |
| 電波 | あてにしない。**電波がなくても普通に使えること** |

## 4. 屋外で困ることと、その対策

| 困ること | アプリ側の対策 |
|---|---|
| 手が汚れる・手袋をしている | ボタンを大きくする。「本当に押しますか？」は出さず、代わりに1回のタップで取り消せるようにする |
| 日差しで画面が見えない | 背景は白、文字は濃い黒。薄いグレーの文字は使わない |
| 電波がない | 機械の中にデータを置く。インターネットにつながらなくても動く |
| 行列が途切れない | 注文を入れてお会計まで、できるだけ少ないタップで終わらせる |
| 片手がふさがる | よく押すボタンは画面の下半分に置く |

## 5. 当日の流れ

```
注文を受ける人                                焼く人
──────────────────────────────────────────────────────
① 注文を聞く
② 商品のボタンを押す（連打すると個数が増える）
③ お名前を聞いて、カタカナで入れる
   ├ 同じ名前の人がすでに待っていたら、服装を2タップで記録
   └ 名前を言いたくない人は、名前を空にして服装だけ記録
④ 「○分ほどお待ちください」と伝える（待ち時間はアプリが出す）
⑤ 預かったお金を入れる → おつりが大きく出る → 確定
                                            ⑥ 一覧を見て、上から順に焼く
⑦ 焼けたら名前で呼ぶ
   「やまださん、お待たせしました」
⑧ 渡す直前に注文の内容で確かめる
   「ステーキ2つですね」
⑨ 「渡した」を押す
```

名前を聞くのを②のすぐ後にしているのは、④の待ち時間の案内と同じ会話の流れでまとめて言えるから。
おつりを渡しながら機械を操作させないようにしている。

## 6. どうやってお客さんを見分けるか（ここが一番大事）

### 6.1 なぜ「お名前」なのか

見分けるための手がかりを比べると、こうなる。

| 手がかり | 似た人と被りにくいか | お客さんが覚えているか | 使えるか |
|---|---|---|---|
| 番号を口で伝える | 被りにくい | **覚えてくれない** | ✕ 札を配らないので無理 |
| 注文の内容 | **3品しかないので被る** | 完璧に覚えている | △ 7組待つと足りない |
| 服装を覚える | ふつう | — | ✕ 今これが壊れている |
| **お名前** | **被りにくい** | **絶対に覚えている** | **◎ これを使う** |

名前は、被りにくくて、お客さんが絶対に覚えていて、しかも呼ばれたら必ず振り向く。
配る物も増えないので、番号札を使わない方針とも合う。

声のかけ方の例：
> 「お名前だけ伺ってもいいですか？焼き上がりでお呼びします」

7組も待っている店なら、お客さん側も納得してくれる。

### 6.2 3段構えにする

1段で完璧にしようとせず、3つ重ねて守る。

| 段 | 何をするか | いつ使うか |
|---|---|---|
| 1段目 | **名前で呼ぶ**（「やまださん」） | 毎回 |
| 2段目 | **渡す直前に注文内容で確かめる**（「ステーキ2つですね」） | 毎回 |
| 3段目 | **服装を記録しておく** | 同じ名前が並んだときだけ |

2段目があるので、万が一1段目で間違えても渡す前に止まる。

### 6.3 服装は「同じ名前が並んだときだけ」記録する

注文を入れた瞬間に、アプリが待っている人の中に同じ名前がいないかを見る。

- いなければ → **何も追加で入れさせない**
- いたら → 「さとうさんが2組待っています」と出して、服装を記録してもらう

**毎回必ず服装を入れる作りにしてはいけない。** 忙しいときに必ず省略されて、機能が死ぬ。
同じ名前が並んだときだけなら、守れる。

### 6.4 服装の選び方

自由に文字を打つのではなく、並んだボタンから選ぶ（2タップで終わる）。

- 色：`黒` `白` `赤` `青` `緑` `黄` `茶` `グレー` `ピンク` `紫`
- 服：`パーカー` `Tシャツ` `シャツ` `ジャケット` `帽子` `ワンピース`
- 連れ：`2人` `3人以上` `家族` `子供連れ`

写真を撮って見分けるのはやらない。断りなく撮ると信用を失うので。

## 7. 画面

### 7.1 注文とお会計（いつも開いている画面）

```
┌────────────────────────────────┐
│  待っている人　7組              │
├────────────────────────────────┤
│  ┌──────────┐  ┌──────────┐    │
│  │ ステーキ  │  │  ○○○    │    │  ← 大きいボタン。連打で個数が増える
│  │  1300円   │  │   600円  │    │
│  │    ×2     │  │          │    │
│  └──────────┘  └──────────┘    │
│                                 │
│  合計  2,600円                  │
│  お名前 [ ヤマダ        ]       │
│  ⚠ 同じ名前の人が待っています    │
│     → 服装を選んでください       │
│                                 │
│  預かり [1000][2000][5000][10000]│
│  ───────────────────────────    │
│       おつり  2,400円            │  ← とても大きく出す
│                                 │
│  [      確定（待ち 約20分）    ] │
└────────────────────────────────┘
```

### 7.2 待っている人の一覧

```
┌──────────────────────────────────┐
│ ▼ 次に渡す人                      │  ← 先頭は常に画面の一番上に固定
│ ③ やまだ さん     ステーキ ×2     │
│    12分20秒待ち   ● 時間かかりすぎ │
│    服装：黒いパーカー              │  ← 同じ名前が並んだときだけ出る
│              [   渡した   ]       │
├──────────────────────────────────┤
│ ④ さとう さん     ステーキ ×1     │
│    8分05秒待ち                    │
│              [   渡した   ]       │
├──────────────────────────────────┤
│ ⑤ すずき さん     ステーキ ×1 ＋○○│
│    3分40秒待ち                    │
└──────────────────────────────────┘
```

7組以上になると画面に収まらないので、**次に渡す人だけは常に一番上に固定**する。

待ち時間を出しておくだけで、**焼き忘れと渡し忘れも一緒に防げる**。
時間がかかりすぎている人はカードの色が変わるので、「お待たせしてすみません」と声をかける判断材料になる。

2人でやるので、機械はスタンドに立てて**焼く人からもこの一覧が見える角度**に置く前提で作る。

### 7.3 今日の売上

- 売上の合計
- 商品ごとに何個売れたか
- 時間帯ごとの売れ方（棒グラフ）
- レジのお金が合っているかの確認（最初に入れたおつり用のお金 ＋ 売上 ＝ 今レジにある現金）

### 7.4 設定

- 商品の名前と値段を直す／商品を隠す
- その日の営業を始める／終わる
- 閉店の時刻を入れる
- データを書き出す

## 8. アプリが覚えておくこと

### その日の営業について
- 日付、イベント名
- 閉店の予定時刻
- 最初にレジへ入れたおつり用のお金

### 商品について
- 名前（例：ステーキ）
- 値段（例：1300円）
- 表示する／隠す
- 並び順

### 1件ごとの注文について
- 通し番号（その日の1件目、2件目…）
- 何をいくつ買ったか、その時の値段
- 合計金額
- 預かったお金、渡したおつり、お会計した時刻
- お客さんの名前（カタカナ）／服装（同じ名前が並んだときだけ）
- 状態（待っている／渡した／取り消した）
- 注文を受けた時刻、渡した時刻

### 大事にしているきまり 3つ

1. **商品の名前と値段は、注文のたびにその時の内容をコピーして残す。**
   現地で「今日は1200円にする」と変えても、前に売った分の記録が壊れない。
   「現地で値段を直せる」を安全にするために、これが必要。

2. **取り消しても記録は消さない。** 「取り消した」という印をつけるだけにする。
   本当に消してしまうと、レジのお金が合わないときに原因を追えなくなる。

3. **商品の残り数は数えない。** 売り切れは人が見て判断する。
   数を管理すると入力も運用も増えるので、今回はやらない。

## 9. 待ち時間の出し方

細かい設定をしなくても出せるようにする。

「渡した」を押した時刻が記録されるので、**最近1組あたり何分で出せているか**が自然に分かる。
これに、前に並んでいる組数を掛けるだけ。

```
最近の1組あたりの時間 × 自分より前に待っている組数 ＝ だいたいの待ち時間
```

営業を始めた直後だけはデータがないので、ざっくりした初期値を使う。
使っていくうちに勝手に正確になる。

## 10. 「もう注文を受けない」の判断

閉店の時刻を入れておくと、
**閉店まで残り時間 ＜ 今の待ち時間** になったときに「これ以上受けない方がいい」と画面に出す。

7組以上待つ屋台で一番こわい「受けたのに出せない」を防ぐため。

## 11. 作り方（どの道具を使うか）

| 何を | 何で | なぜ |
|---|---|---|
| 画面 | React ＋ TypeScript | 画面の状態を素直に書ける。情報も多い |
| 組み立て | Vite | 軽くて速い |
| 見た目 | Tailwind CSS | ボタンを大きくする、文字を濃くするといった調整が速い |
| 形 | **ホーム画面に置けるWebアプリ**（PWA という作り） | アプリストアを通さずに、アイコンから全画面で開ける。電波がなくても動く |
| 保存場所 | 機械の中（IndexedDB という保存領域） | 営業中に消えない。件数が増えても耐える |
| 置き場所 | Vercel か GitHub Pages | 無料で、必要な条件（HTTPS）も満たす |
| サーバー | **最初は作らない** | 電波がない現場で動かなくなるのを避けるため |

## 12. データを消さないための工夫

売上のデータが消えるのが一番こわいので、ここは厚くする。

- お会計を確定するたびに、その場で機械の中へ書き込む（後でまとめて保存しない）
- 営業を終えるときに、**必ずデータの書き出しを通る**流れにする
- 使う機械とブラウザは固定する。シークレットモードでは使わない（README に書く）

## 13. 今回は作らないもの

わざと作らない。屋台のレジではかえって邪魔になるため。

- **商品の残り数・在庫の管理**
- お客さんの登録、ポイント、会員
- 原価や仕入れの管理
- PayPay やカードでの支払い（現金だけ）
- レシートの印刷
- 2台目の機械との同期（将来「見るだけの2台目」を足せる余地だけ残す）
- 写真でお客さんを見分ける
- 消費税の内訳表示（税込の値段で記録しておき、必要なときに計算する）
