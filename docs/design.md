# 屋台にのきち レジアプリ 設計メモ

## 1. 何のためのアプリか

屋台「にのきち」でステーキ（1300円）ほか最大3品を売るときに使うアプリ。

一番困っているのは **焼き上がった商品を誰に渡せばいいか分からなくなること**。
だからこれは「お金を計算するアプリ」ではなく、
**お会計の済んだお客さんと、焼き上がった商品を結びつけるアプリ**として作る。

## 2. 中心にある考え方：チケット

**1つの注文 ＝ 1枚のチケット。**

```
お会計する  →  チケットが生まれる
                    ↓
            「受け取り待ち」の一覧に並ぶ
                    ↓
            商品を渡す → チケットが消える
```

アプリがやることは、ほぼこれだけ。

### チケットに書いてあること

| 項目 | 例 | 入力の手間 |
|---|---|---|
| 番号 | ③ | なし（自動） |
| 商品 | ステーキ ×2 | 注文を入れたときに入る |
| お会計 | お会計済み | なし（先払いなので必ず済んでいる） |
| 見分けるための印 | 黒 ／ ヤマダ | **1タップ**（または打ち込み） |
| 待っている時間 | 12分20秒 | なし（自動） |

### 「消える」について

一覧からチケットは消えるが、**売上の記録としては残す**。
本当に消してしまうと、片付けのときにレジのお金が合わなかったときに原因を追えなくなるため。

## 3. 直したいこと（困っている順）

1. 焼き上がった商品を、別のお客さんに渡してしまう
2. もう払った人に、もう一度お会計をしてしまう
3. 忙しいと注文そのものを忘れる・渡し忘れる
4. 片付けたあと、レジのお金と売上が合わない
5. 次回の仕込み量が勘になる

原因は **服装や顔を覚えて見分けていること**。
お客さんは動くし、上着を脱ぐし、似た服装の人も並ぶ。
しかも一番忙しいときに限って覚えきれなくなる。

## 4. 使う場面の決まりごと

| 項目 | 内容 |
|---|---|
| 商品 | 1〜3品。**名前と値段を現地で直せること**（3品目は未定でも動く） |
| 使う機械 | **スマホかタブレットを1台だけ。増やさない** |
| 支払い | **現金だけ** |
| お金をもらう時 | **先払い**（注文を聞いたその場でもらう） |
| 人数 | 2人（焼く人と、注文を受ける人） |
| 機械を持つ人 | 注文を受ける人。**呼び出しと受け渡しも同じ人が行う** |
| 焼く人への伝達 | 口で伝える（アプリは使わない） |
| 混むとき | **7組以上**が同時に待つ。焼く時間も長め |
| 番号札 | **配らない** |
| 電波 | あてにしない。**電波がなくても普通に使えること** |

## 5. 一番の決まりごと：入力は速さを優先する

**入力に時間はかけられない。タップも少ないほうがいい。**
機能を足すかどうかは、まずこの基準で判断する。

- 追加の入力は **1注文あたり1タップまで**
- 「本当によろしいですか？」は出さない（タップが増えるので）。代わりに**後から戻せる**ようにする
- 文字を打たせるのは、本人が打ちたいときだけ

## 6. どうやってお客さんを見分けるか

### 6.1 なぜ「服の色」なのか

| 入れるもの | タップ数 | 被りにくさ | お客さんが覚えているか |
|---|---|---|---|
| 番号を口で伝える | 1 | 高い | **覚えてくれない** |
| 名前（カタカナ） | キーボードを開いて3〜6 | 高い | 絶対に覚えている |
| **服の色** | **1** | ふつう | 覚える必要がない |
| 注文の内容 | **0**（もう入っている） | 低い（3品しかない） | 完璧に覚えている |

**色は1タップで終わる。これが一番速い。**

ただし色だけでは、7組いれば黒い服の人が2人来る。
そこで **もう入っている「注文の内容」と組み合わせる**。

> `ステーキ×2 ／ 黒`

追加のタップは1回だけで、かなり絞れる。

### 6.2 役割を分ける

| 場面 | 使うもの | タップ |
|---|---|---|
| **呼ぶ** | 注文の内容（「ステーキ2つでお待ちの方！」） | 0 |
| **絞る** | 服の色（複数人来たら黒い服の人を見る） | 0（見るだけ） |
| **渡す直前に確かめる** | 注文の内容（「ステーキ2つですね」） | 0 |

お客さんは自分の注文を覚えているので、内容で呼べば手を挙げてくれる。
**色はこちらが見るための印なので、お客さんに覚えてもらう必要がない。** ここが番号札と決定的に違う。

渡す直前にもう一度内容で確かめるので、万一色で間違えても渡す前に止まる。

### 6.3 名前も同じ欄に入れられるようにする

名前のほうがよさそうな場面もあるので、**どちらか一方に決めない。**
「見分けるための印」という1つの欄に、色のボタンでも、打ち込んだ名前でも入るようにする。

- ふだんは色のボタンを1タップ
- 名前を聞きたいときは文字で打つ

**どちらがよいかは1回出店すれば分かるので、今は決めない。**

### 6.4 色の選択肢

よく着られている色を優先して並べる。

`黒` `白` `グレー` `紺` `青` `赤` `ピンク` `緑` `黄` `茶` `紫` `柄物`

同じ色の人が同時に待っている場合だけ、2段目として服の種類を出す（これも1タップ）。

`パーカー` `Tシャツ` `シャツ` `上着` `帽子` `ワンピース`

**ふだんは2段目を出さない。** 毎回出すと必ず省略されて機能が死ぬ。

写真を撮って見分けるのはやらない。断りなく撮ると信用を失うため。

## 7. 画面

### 7.1 注文とお会計

```
┌──────────────────────────────────┐
│  受け取り待ち　7組                │
├──────────────────────────────────┤
│  ┌────────────┐  ┌────────────┐  │
│  │  ステーキ   │  │   ○○○     │  │  ← 連打で個数が増える
│  │   1300円    │  │    600円   │  │
│  │     ×2      │  │            │  │
│  └────────────┘  └────────────┘  │
│                                   │
│  合計  2,600円                    │
│                                   │
│  見分ける印                        │
│  ■■■■■■■■■■■■              │  ← 色のボタンを1タップ
│  黒白灰紺青赤桃緑黄茶紫柄          │
│  [ 名前を打つ ]                   │
│                                   │
│  預かり [1300][2000][3000][5000]  │
│  ────────────────────────────    │
│       おつり  400円                │  ← とても大きく出す
│                                   │
│  [        確定（待ち 約20分）    ] │
└──────────────────────────────────┘
```

最短のタップ数（ステーキ1つ、2000円預かり）：

| | 操作 |
|---|---|
| 1 | `ステーキ` を押す |
| 2 | `黒` を押す |
| 3 | `2000` を押す（おつりが大きく出る） |
| 4 | `確定` を押す |

**4タップ。** おつりの計算が要らないときは預かりを飛ばせるので **3タップ**。

- 色を押さずに確定してもよい（止めない）
- 預かりを入れずに確定してもよい（おつりの計算なしで記録される）
- 画面の移動を入れない。全部この1画面で終わる

### 7.2 受け取り待ちの一覧

```
┌──────────────────────────────────┐
│ ▼ 次に渡す                        │  ← 先頭は常に画面の一番上に固定
│ ③  ステーキ ×2        お会計済み  │
│     ■ 黒                          │  ← 色の名前ではなく、色そのものを面で出す
│     12分20秒   ● お待たせしている  │
│            [  受け取り済み  ]     │
├──────────────────────────────────┤
│ ④  ステーキ ×1        お会計済み  │
│     ■ 紺                          │
│     8分05秒                       │
│            [  受け取り済み  ]     │
├──────────────────────────────────┤
│ ⑤  ステーキ ×1 ＋ ○○○  お会計済み │
│     ヤマダ                        │
│     3分40秒                       │
└──────────────────────────────────┘
```

- `受け取り済み` を **1タップ**でチケットが消える
- 押し間違いに備えて、**5秒間だけ「戻す」が出る**（「本当に消しますか？」は出さない）
- 7組以上は画面に収まらないので、**次に渡す1枚は常に一番上に固定**する
- **色は文字ではなく色の面で出す。** 「黒」と読むより、黒い四角を見るほうが速い
- 待っている時間を出すだけで、**焼き忘れと渡し忘れも一緒に防げる**。時間がかかりすぎたらカードの色が変わる
- 間違えて作ったチケットや、待ちきれず帰ってしまったお客さんの分は、長押しで取り消せる（よく使う操作ではないので、ふだんの導線には置かない）

### 7.3 今日の売上

- 売上の合計
- 商品ごとに何個売れたか
- 時間帯ごとの売れ方
- レジのお金が合っているかの確認（最初に入れたおつり用のお金 ＋ 売上 ＝ 今レジにある現金）

### 7.4 設定

- 商品の名前と値段を直す／商品を隠す（**3品目が決まっていなくても始められる**）
- その日の営業を始める／終わる
- 閉店の時刻を入れる
- データを書き出す

## 8. アプリが覚えておくこと

### その日の営業について
- 日付、イベント名
- 閉店の予定時刻
- 最初にレジへ入れたおつり用のお金

### 商品について
- 名前（例：ステーキ）
- 値段（例：1300円）
- 表示する／隠す
- 並び順

### チケット1枚ごと
- 番号（その日の1枚目、2枚目…）
- 何をいくつ買ったか、そのときの値段
- 合計金額
- 預かったお金、渡したおつり、お会計した時刻
- 見分けるための印（色 ／ 服の種類 ／ 名前。どれも空でよい）
- 状態（受け取り待ち ／ 渡した ／ 取り消した）
- 作った時刻、渡した時刻

### 大事にしているきまり 3つ

1. **商品の名前と値段は、チケットごとにそのときの内容をコピーして残す。**
   現地で「今日は1200円にする」と変えても、前に売った分の記録が壊れない。
   「現地で値段を直せる」を安全にするために、これが必要。

2. **渡しても、取り消しても、記録は消さない。** 一覧から見えなくなるだけ。
   本当に消すと、レジのお金が合わないときに原因を追えなくなる。

3. **商品の残り数は数えない。** 売り切れは人が見て判断する。
   数を管理すると入力も運用も増えるので、今回はやらない。

## 9. 待ち時間の出し方

細かい設定をしなくても出せるようにする。

「受け取り済み」を押した時刻が残るので、**最近1組あたり何分で出せているか**が自然に分かる。
これに、前に並んでいる組数を掛けるだけ。

```
最近の1組あたりの時間 × 自分より前に待っている組数 ＝ だいたいの待ち時間
```

営業を始めた直後だけデータがないので、ざっくりした初期値を使う。
使っていくうちに勝手に正確になる。

## 10. 「もう注文を受けない」の判断

閉店の時刻を入れておくと、
**閉店まで残り時間 ＜ 今の待ち時間** になったときに「これ以上受けない方がいい」と画面に出す。

7組以上待つ屋台で一番こわい「受けたのに出せない」を防ぐため。

## 11. 屋外で困ることと、その対策

| 困ること | アプリ側の対策 |
|---|---|
| 手が汚れる・手袋をしている | ボタンを大きくする。確認は出さず、後から戻せるようにする |
| 日差しで画面が見えない | 背景は白、文字は濃い黒。薄いグレーの文字は使わない |
| 電波がない | 機械の中にデータを置く。インターネットにつながらなくても動く |
| 行列が途切れない | 1件を3〜4タップで終わらせる。画面の移動を入れない |
| 片手がふさがる | よく押すボタンは画面の下半分に置く |

## 12. アプリが止まっても注文が消えない仕組み

**ここが設計で一番大事なところ。**
混んでいる最中に受け取り待ちが消えたら、取り返しがつかない。

### 12.1 どういう壊れ方があるか

| 壊れ方 | 起きやすさ | 守れるか |
|---|---|---|
| アプリ（タブ）が落ちた | よく起きる | **◎ 完全に守れる** |
| 他のアプリを使って戻ったら、画面が読み込み直された | iPhoneでよく起きる | **◎ 完全に守れる** |
| スマホの電源が切れた・再起動した | 起きる | **◎ 完全に守れる** |
| 間違ってブラウザを閉じた | 起きる | **◎ 完全に守れる** |
| 長く使わないとブラウザがデータを消す（iPhoneは7日） | 週1回の出店なら起きうる | ○ 書き出したファイルから戻せる |
| スマホ自体が壊れた・水没した・充電できない | まれ | ✕ アプリでは守れない（運用で備える） |

**ふだん起きる壊れ方は全部守れる。** ここを確実にする。

### 12.2 「ノートに追記する」やり方にする

よくある作り方は、注文が変わるたびに**全部をまとめて書き直す**。これは危ない。
書き直している途中で止まると、**全部が壊れる**。

そうではなく、**ノートに1行ずつ追記していく**やり方にする。

```
19:30:12  ①を作った  ステーキ×1  黒    1300円 預かり2000 おつり700
19:31:40  ②を作った  ステーキ×2  紺    2600円 預かり3000 おつり400
19:38:05  ①を渡した
19:39:22  ③を作った  ステーキ×1  ヤマダ 1300円 ちょうど
19:41:03  ②を渡した
```

**前の行は絶対に書き換えない。**
だから、新しく書いた行が失敗しても、前の行は無傷で残る。
最悪でも **今まさに押した1件だけ**。7組全部が消えることは、仕組みのうえで起きない。

アプリを開いたときは、この行を上から全部読んで、今の状態を組み立てる。

### 12.3 「あとでまとめて保存」を絶対にしない

`確定` を押した **その瞬間**に書く。1秒も後回しにしない。

「30秒ごとに保存」のような作りにはしない。その30秒の間に落ちたら消えるため。

### 12.4 開いたら、勝手に続きから始まる

```
┌──────────────────────────────┐
│   前回の続きから復帰しました   │
│                               │
│   受け取り待ち　7組            │
│   最後の記録  19:42:03         │
│                               │
│     [   このまま続ける   ]     │
└──────────────────────────────┘
```

何も操作しなくても元に戻る。「データを読み込む」ボタンを押させたりしない。

### 12.5 画面にいつも「保存できている」と出す

パニックの正体は、消えたかどうか **分からない** こと。だから常に見せる。

- 画面の端に `保存OK 19:42:03` といつも出しておく
- 保存に失敗したら、赤くして大きく警告する（容量が足りない、など）

### 12.6 自分で試せるようにする

設定画面に **「今すぐ試す」** ボタンを置く。
押すと画面をわざと読み込み直して、ちゃんと戻ってくるのを **自分の目で確認できる**。

本番前にこれを1回押しておけば、「落ちても大丈夫」と確信を持って営業に入れる。

### 12.7 ファイルに書き出して持っておく

スマホの中のデータが消える場合（iPhoneの7日ルールなど）に備える。

- 営業が終わるときに、**必ず書き出しを通る**流れにする
- 営業中でも1タップで書き出せる（混む前に1回やっておくと安心）
- 書き出したファイルは、**読み込んで元に戻せる**ようにする

### 12.8 アプリでは守れないこと（運用で備える）

- **モバイルバッテリーを必ず持つ。** 常に充電しながら使う
- **ホーム画面のアイコンから開く。** ブラウザのタブから開かない
- **シークレットモードでは絶対に使わない**（閉じると全部消える）
- 使う端末は1台に固定する

## 13. 作り方（どの道具を使うか）

**素のJavaScriptとHTMLだけで作る。** スマホだけで中身を直せることを優先する。

| 何を | 何で | なぜ |
|---|---|---|
| 全体 | **HTMLファイル1つ**（素のJavaScript） | スマホだけで直せる。組み立ての道具がいらない |
| 見た目 | HTMLの中にCSSを直接書く | ファイルを分けない。1つ見れば全部分かる |
| 保存場所 | **localStorage** | 素のJavaScriptから一番素直に書ける。**書いた瞬間に確実に残る** |
| 電波なしで開く | `sw.js`（20行ほど） | 一度書いたら触らない |
| ホーム画面のアイコン | `manifest.json`（10行ほど） | 全画面で開ける。一度書いたら触らない |
| 置き場所 | GitHub Pages | 無料。HTTPS なのでホーム画面に追加できる |
| ビルド・npm・React | **使わない** | スマホで直せなくなるため |

ファイルは3つだけ。**ふだん直すのは `index.html` だけ。**

### なぜ localStorage なのか

- 書いた瞬間に確実に残る。落ちる直前でも取りこぼしにくい
- もう1つの選択肢（IndexedDB）は「後から結果が返ってくる」作りなので、素のJavaScriptだと書き方が難しくなる
- 1日数百件でも数十KB。容量の心配はない
